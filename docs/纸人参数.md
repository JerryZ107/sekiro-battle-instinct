# 纸人（Spirit Emblem / 形代）param 字段与一键补丁

> 结论：纸人上限、初始纸人、纸人漂流给的数量都不是 DLL 能直接改的。
> 网上同类 mod（含本机装的那套 mod 包）走的都是「改 regulation 参数表」这条现成路线，
> 即 mods\param\gameparam\gameparam.parambnd.dcx 里的固定字段。
> 仓库提供 tools\patch_paper_params.ps1 一键改这几个字段（自动备份、可回滚，实测只动 9 个字节）。

## 字段表（Resurrection / 当前包实测）

| 目标 | param | 行 id | 偏移 | 原值 | 改成 |
| --- | --- | --- | --- | --- | --- |
| 纸人上限 | EquipParamGoods | 1000 纸人 | +0x36 (u16) | 15 | 30 |
| 临时纸人上限 | EquipParamGoods | 1001 临时纸人 | +0x36 (u16) | 5 | 15 |
| 纸人漂流给多少 | EquipParamGoods | 3800 纸人漂流(形代変換_有) | +0x8C (u16) | 5 | 15 |
| 初始纸人 | ResourceItemParam | goodsId=1000 行 | +0x10 (u32) | 6 | 30 |
| 成长 f1 | ResourceItemParam | goodsId=1000 行 | +0x14 (f32) | 3.75 | 基础上限/4 |
| 成长 f2 | ResourceItemParam | goodsId=1000 行 | +0x18 (f32) | 6.25 | 满上限/4 |
| 成长 f3 | ResourceItemParam | goodsId=1000 行 | +0x1C (f32) | 5.0 | 上限技能个数 |
| 成长 f4 | ResourceItemParam | goodsId=1000 行 | +0x20 (f32) | 25.0 | 满上限 |

依据（可复现）：

- EquipParamGoods 1000 / 1001 的调试名分别是「リソースアイテムA（白形代）」「一時リソースアイテムA（補充白形代）」，即纸人 / 临时纸人；
  3800 是「【補充】形代変換_有」，即纸人漂流；+0x36 / +0x8C 的数值正好等于 HUD 上限与单次补充量。
- 本机另一套 mod 包把这三个字段改成了 20 / 15 / 10，其余字节完全相同，说明这就是纸人上限类 mod 的标准改法。

## 「每个提升纸人上限的技能 +N」

5 个技能在 SkillParam 里，行 id 75 / 76 / 175 / 176 / 603，名字就是 形代所持上限+1A…+1E
（日文 能力強化_形代の所持上限UP（A〜E））。

- 每个技能 +1 是游戏按「已获得技能」计数给的：SkillParam 行里只有一位标志（+0x34 的 0x01000000 位 = 该技能会加上限），
  没有「加多少」的数值字段，所以纯 param 改不出「每个技能 +10」。
- param 侧唯一入口是 ResourceItemParam 里那 4 个浮点（+0x14/+0x18/+0x1C/+0x20）。原包 3.75 / 6.25 / 5 / 25
  正好是 15/4、25/4、5 个技能、25 满级上限 —— 即基础上限 15、满级 25、5 个技能，每技能 (25-15)/5 = 2，
  与你观察到的「1~2 个」一致。
- 所以工具按 基础上限 30 + 每技能 10 × 5 = 80 写入：7.5 / 20 / 5 / 80。若游戏走这条公式，
  学满 5 个技能后上限 = 30 + 50 = 80。
- 这条属于推断字段：进游戏看 HUD 上限即可验证。不对就回滚，或加 -SkipGrowthFloats 只打确定项。

## 用法

    # 只看不改
    powershell -ExecutionPolicy Bypass -File tools\patch_paper_params.ps1

    # 应用（自动备份 <文件>.bak-时间戳）
    powershell -ExecutionPolicy Bypass -File tools\patch_paper_params.ps1 -Apply

    # 只打确定项
    powershell -ExecutionPolicy Bypass -File tools\patch_paper_params.ps1 -Apply -SkipGrowthFloats

    # 自定义数值
    ... -Apply -InitialPaper 30 -BaseCap 30 -PerSkillBonus 10 -TempCap 15 -DriftAmount 15

    # 回滚（用最近一次备份覆盖）
    powershell -ExecutionPolicy Bypass -File tools\patch_paper_params.ps1 -Revert

流程：解 DCX（DFLT/zlib）→ 定位 EquipParamGoods / ResourceItemParam 行 → 按表改字段 → 重新压回 DCX 并复读校验。

注意：这是全局参数改动，与「只对某个存档生效」无关；其它 mod 覆盖了同一个 param 文件后需要重跑一次。

## 老存档：运行时修正（src/emblem.rs）

param 只能改「新存档的初始值」：纸人上限是**学技能时由游戏写进存档**的，
所以老存档（技能已学完）不会因为改 param 而涨。`src/emblem.rs` 负责这部分：

- 探针（cfg 默认开）：每秒把 PlayerData 里等于 HUD 上限/数量的字段、InventoryData 里
  1000/1001/1020/1021 号物品的 (id,count) 记录写进 battle_instinct.log（前缀 `emblem probe:`），
  并列出「像上限的小整数」候选（`candidate` 行）与变化字段（`u32 a -> b` 行）。
- 修正（填了 `纸人上限偏移` 且 `纸人上限功能: 开` 才生效）：每帧把上限写回
  `纸人基础上限 + 每个上限技能加成 × 已习得技能数`；技能数可配置，或按当前上限自动推算
  （30+10k 优先，其次按老存档 15+2k），学到新技能时（比上次写入值多 1~4）自动 +1。
- 未填偏移时**只探测、绝不写内存**。

cfg 键（battle_instinct.cfg 末尾，中英两份）：纸人上限功能 / 纸人探针 / 纸人基础上限 /
每个上限技能加成 / 上限技能数 / 已习得上限技能数 / 纸人上限偏移 / 纸人上限宽度 /
已学技能数偏移 / 旧基础上限 / 旧每技能加成 / 探针上限值 / 探针数量值 / 探针窗口。

定位技巧：在 cfg 里把「探针上限值」填成 HUD 上看到的纸人上限、「探针数量值」填当前纸人数，
探针会直接把这些数值在内存里的位置打出来（`== HUD 上限/数量` 行），一次就能定位。

## 运行时字段（已定位，2026-09-27 实测）

| 目标 | 位置 | 说明 |
| --- | --- | --- |
| 纸人上限（游戏真正用的那个） | `PlayerData + 0x146` (u16) | 存档里同一份 = `sen(0x7C) + 0xCA`；老存档写这个才生效 |
| 纸人上限（存档副本，改它没用） | `PlayerData + 0x170` (u16) | 之前误判成上限，已由 cfg 的 `纸人还原偏移/还原值` 写回 25 |
| 上限成长参考值 | `ResourceItemParam goodsId=1000` | 15→25 那套；真正显示值靠上面那个字段 |

参数关系（实测）：纸人上限 = **基础上限 + 每个「形代所持上限」技能加成 × 已学技能数**；
vanilla 是 `15 + 1×5 = 20`，本 mod 默认改成 `25 + 5×5 = 50`（都可在 cfg 里改）。

cfg 里现在可调：

```
# 纸人基础上限: 25          ← DLL 实时（改完重进游戏）
# 每个上限技能加成: 5        ← DLL 实时
# 上限技能数: 5
# 纸人漂流上限: 9            ← param 侧（血纸人上限 + 一次给的数量），需跑 tools 脚本
# 初始纸人: 30               ← param 侧（开局携带），需跑 tools 脚本
```

param 侧改完后跑一次：

```powershell
powershell -ExecutionPolicy Bypass -File tools\patch_paper_params.ps1 -Apply
```

脚本会**直接读 battle_instinct.cfg 里的这四个数**，不用重复传参。

## cfg 精简（只有三个可调项，2026-09-27 起）

```ini
# 纸人初始上限: 25     ← 上限 = 初始上限 + 技能增加上限 × 已学「形代所持上限」技能数（DLL 实时，重进游戏生效）
# 技能增加上限: 5
# 纸人漂流: 9          ← 血纸人(临时纸人)上限 + 一次给的数量（param 侧，改完跑一次 tools 脚本）
```

技术参数已固定进代码（正常不用动，仍然可以通过同名注释覆盖）：

| 参数 | 固定值 | 说明 |
| --- | --- | --- |
| 纸人上限功能 | 开 | 不写这项也默认开 |
| 纸人上限偏移 / 宽度 | `0x146` / 2 | 运行时真正用的上限字段 |
| 纸人还原偏移 / 值 | `0x170` / 25 | 之前误写字段的补写（一次性） |
| 上限技能数 | 5 | 「形代所持上限」技能总数 |
| 旧基础上限 / 旧每技能加成 | 15 / 1 | 老存档（vanilla 15+1×n）反推用 |
| 探针 / 探针窗口 | 关 / 0x1000 | 需要重新定位字段时才开 |

另：`battle_instinct_emblem.state`（游戏目录，自动生成）记录「已学上限技能数」——
这样改 `纸人初始上限` / `技能增加上限` 后不会重新算错；删掉它会按当前上限重新推算。

## 重要：内存 param 补丁 = 实验性，默认关闭（2026-09-27）

DLL 里尝试过「自己扫内存找 param 行并改写」，结论是**不可行**：

- 扫私有堆：6.7 GB 全扫完，锚点命中数 0（param 不在堆里）
- 扫文件映射（`MEM_MAPPED` ≤64MB）：会碰到游戏 mmap 的页面，触发大量换页 I/O → **游戏卡死**
- param 的实际存放：要么是磁盘上的 `gameparam.parambnd.dcx`（DCX/DFLT 压缩，DLL 里没有 zlib 无法解压），
  要么在游戏自己读出来的缓冲区里（位置不稳定）

所以最终方案：

| 项目 | 谁负责 |
| --- | --- |
| 纸人上限（含老存档修正）、每技能加成、总开关 | **DLL 实时**（写 `PlayerData+0x146`，已验证） |
| 纸人漂流数量/上限、初始纸人、上限成长浮点 | **param 文件**，用 `tools/patch_paper_params.ps1` 一次性写入 |

`# 纸人内存参数: 开` 仍然存在（实验用），**默认关**，不建议开启。

## 玩家安装（3 个文件）

```
dinput8.dll
battle_instinct.cfg
纸人挂.bat        ← 改完 cfg 双击它
```

把三个文件放进 Sekiro 目录（`sekiro.exe` 旁边）→ 双击 `纸人挂.bat` 一次即可。
- 开关：cfg 里 `纸人上限功能: 开/关`（关 = 不写任何 param）
- 回滚：`纸人挂.bat revert`
- 只改「纸人初始上限 / 技能增加上限」：改 cfg → 重进游戏（DLL 实时，无需跑 bat）
- 只改「纸人漂流」：改 cfg → 双击 `纸人挂.bat`

## 发布形态（2026-09-27 起：只有 3 个文件）

发布包 = `dinput8.dll` + `battle_instinct.cfg` + `纸人挂.bat`。

`纸人挂.bat` 把 `tools/patch_paper_params.ps1` 的代码**原样嵌在文件尾部**，运行时：
1. `chcp 936`，设置 `PAPERDOLL_CFG=%~dp0battle_instinct.cfg`
2. 用 PowerShell 把自身第 41 行之后的内容抽到 `%TEMP%\zhiren_*.ps1`
3. `powershell -File 临时脚本 -Apply`（脚本自己读 `PAPERDOLL_CFG`；`纸人挂.bat revert` 会设 `PAPERDOLL_REVERT=1` 触发回滚）
4. 删掉临时文件

好处：玩家不用管 `.ps1`，也只放三个文件；源码仍在 `tools/patch_paper_params.ps1`（开源可读），
改完跑 `just bat`（或 `tools/make_bat.ps1`）重新生成 bat 即可。
